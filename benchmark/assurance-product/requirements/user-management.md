# 用户管理模块测试需求

测试 vue-fastapi-admin 的用户管理（users）模块，仅覆盖 API 层，执行完整 full workflow。

## 范围

- `GET /api/v1/user/list`：分页、用户名/邮箱筛选、部门筛选及部门信息展示。
- `GET /api/v1/user/get`：按用户 ID 查询。
- `POST /api/v1/user/create`、`POST /api/v1/user/update`、`DELETE /api/v1/user/delete`。
- `POST /api/v1/user/reset_password`：普通用户密码重置及超级管理员保护。
- 用户接口的认证、管理权限，以及角色/部门关联的一致性。
- 登录接口仅用于验证本轮测试账号创建、启停和密码重置的效果，不扩展为独立认证模块测试。

## Benchmark 非交互确认

以下范围由 benchmark owner 确认，作为本 item 的验收输入：

- 创建、查询、修改、删除的正常流程和缺少必填字段的输入边界。
- 邮箱格式、用户名/邮箱唯一性，以及更新时的邮箱冲突。
- 无效部门 ID、部门 ID 类型、无效角色 ID，以及操作失败后的关联与用户数据一致性。
- 用户详情和列表不得泄露密码字段；部门信息补充不得使正常的用户查询失效。
- 未登录或权限不足的请求不能操作用户管理接口；按项目已发布的 `.aa/data-knowledge.yaml`
  中 `entities.user.constraints` 验证权限和关联约束，不自行添加密码复杂度或长度阈值。
- 普通用户密码重置后，按实现公开的重置契约验证新密码可登录、原密码不再有效；
  超级管理员的重置请求必须被拒绝，不得修改其密码。

## 数据与证据边界

- 所有创建、修改、删除、启停和重置操作仅针对本轮创建的测试账号和关联数据。
  不修改或删除初始化管理员及 benchmark driver 的运行身份。
- 使用独立 SUT 副本、独立运行数据库和新的 change ID。保留原部门 item 的目录、测试和证据。
- 测试数据采用本轮唯一前缀、合法邮箱和可回收的角色/部门；负向用例避免先被无关输入错误拦截。
- 计划和代码中的身份来源必须有项目事实依据；不向 init 产物写入管理员用户名或密码，
  不假设 `admin / admin`，不改用新的 opaque-token 方案。
- 记录真实的失败及流程证据，不修改 SUT 业务代码，不自动提交外部缺陷单。
